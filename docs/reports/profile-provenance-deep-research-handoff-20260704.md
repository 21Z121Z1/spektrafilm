## Key Existing Evidence

Spektrafilm profile schema requires these profile-data fields:

- `wavelengths`
- `log_sensitivity`
- `channel_density`
- `base_density`
- `midscale_neutral_density`
- `log_exposure`
- `density_curves`
- `density_curves_layers`
- `density_curves_model`

Relevant code: `src/spektrafilm/profiles/io.py`, especially `ProfileData`.

README currently says Kodak Portra 400 CMY diffuse densities are generic:

- `README.md:64-67`: Portra 400 is shown from data-sheet E-4050, but the CMY diffuse densities are generic because they are usually not published.

Internal source-material discussion says profile creation is not only digitizing curves:

- `docs/spectral_film_simulations.md:3482-3486`: profile creation includes channel unmixing and manual adjustment; separate CMY dye diffuse densities are often unavailable and must be reconstructed to respect available data.

Verified external seed finding:

- Kodak Portra 400 official E-4050 current PDF, revised 2025-01, page 4: `Spectral-Dye-Density Curves` contains only `Midscale Neutral` and `Minimum Density`, not separate Cyan/Magenta/Yellow dye-density curves.
- Kodak Portra 400 older E-4050 2016 PDF has the same structure.
- Kodak Professional Portra Endura / Supra Endura E-4021 PDF, page 8: `Spectral-Dye-Density Curves` does show separate `Yellow`, `Magenta`, and `Cyan` curves.

Preliminary local numeric check:

- `kodak_portra_400.data.channel_density` can approximately reconstruct `midscale_neutral_density` from `base_density` with least-squares CMY weights `[0.755136, 0.776661, 0.952619]`.
- The Portra 400 reconstruction error against bundled `midscale_neutral_density` is about max `0.028537D`, mean `0.008551D`.
- `kodak_portra_endura` reconstructs bundled midscale neutral essentially exactly from its C/M/Y curves, consistent with the official paper datasheet exposing separate dye-density curves.

Interpretation: Portra 400 CMY curves are plausibly constrained/generated decomposition curves, not official separately published Kodak dye curves.

## Research Questions

For each bundled profile:

1. What external documents correspond to this profile?
2. Which exact curves are present in the external documents?
3. Which Spektrafilm profile fields are directly supported by those documents?
4. Which Spektrafilm profile fields are reconstructed/generated, inferred, optimized, or manually adjusted?
5. Are there mismatches between source labels and JSON fields, such as:
   - C/M/Y dye-density curves shown in Spektrafilm but absent from datasheet
   - only composite `minimum density` / `midscale neutral` source curves available
   - channel curves apparently copied from a related stock or paper
   - push profiles derived from another stock without distinct source curves
   - Fujifilm profiles missing characteristic density curves or relying on non-manufacturer approximations
   - paper profiles using film-like assumptions
6. Which curves need repair, and what kind of repair is possible without new physical measurements?

## Important Definition Of "Repair"

The user does not have physical Portra 400 film or a spectrophotometer. Without new measurements, repair can only mean:

- Better provenance labels and docs.
- Better constrained reconstruction from published Min/Mid, sensitivity, characteristic curves, and plausible physical priors.
- Better internal consistency across `base_density`, `midscale_neutral_density`, `channel_density`, `density_curves`, and neutral-print behavior.

It cannot mean:

- Recovering the true manufacturer CMY dye absorption spectra when they were never published.
- Claiming generated curves are measured curves.

Use the following repair tiers:

- Tier 0: documentation/metadata fix only.
- Tier 1: constrained profile refit from available public sources and physical priors.
- Tier 2: requires real measurement or an external published measurement set.

## Source Search Instructions

Search for each profile's manufacturer datasheet by:

- Manufacturer product name.
- Kodak publication number, if known: examples include E-4050 for Portra 400 and E-4021 for Portra Endura / Supra Endura.
- Cine product codes: e.g. 5203/7203 for Vision3 50D, 5207/7207 for Vision3 250D, 5213/7213 for Vision3 200T, 5219/7219 for Vision3 500T, 2383, 2393.
- Fuji official datasheet names and archived PDFs.
- Internet Archive snapshots for manufacturer PDFs.
- Reputable mirror sites only when original sources are unavailable. Label mirrors clearly.

Prefer these source classes in order:

1. Current manufacturer PDF.
2. Archived manufacturer PDF.
3. Manufacturer technical publication or product brochure.
4. Scientific paper with measured curves.
5. Credible mirror of a manufacturer PDF.
6. Community discussion only as context, not as proof.

For each source, record:

- URL
- publication number
- revision date
- page number
- exact curve names visible in the source
- whether the curve is visually/digitally extractable
- whether the source is primary, archived primary, mirror, or secondary

## Field-Level Audit Matrix

For each profile, produce one row per field:

| Profile | Field | Source Support | Source URL/Page | Classification | Confidence | Repair Tier | Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |

Use these `Classification` values:

- `direct-source`: curve exists in source with same semantics.
- `source-composite`: source has composite curve only, but profile stores decomposed channels.
- `reconstructed`: profile field is inferred from available source curves.
- `optimized`: profile field was tuned to runtime behavior or neutral-print constraints.
- `generic`: generic or stock-family prior, not profile-specific.
- `derived-from-related-profile`: copied/adapted from another stock or print medium.
- `unknown`: cannot determine.
- `likely-wrong`: source conflict or physically suspicious mismatch.

Use these `Repair Tier` values:

- `none`
- `metadata-only`
- `constrained-refit`
- `needs-measurement`
- `needs-author-clarification`

## Specific Checks To Run

For each profile:

1. Compare manufacturer datasheet curve availability with JSON fields.
2. Determine if `channel_density` has actual C/M/Y source curves or is a generated decomposition.
3. Determine if `base_density` and `midscale_neutral_density` are direct source curves or reconstructed.
4. Determine if `log_sensitivity` is direct source data or shifted/filtered/retouched.
5. Determine if `density_curves` are direct characteristic curves or modified for neutral print behavior.
6. Treat `density_curves_layers` and `density_curves_model` as likely generated unless a source explicitly provides layer sub-curves.
7. Identify push profiles that likely derive from the base profile rather than independent source data.
8. Flag any profile where source has only two composite dye-density curves but Spektrafilm displays three C/M/Y curves without clear labeling.
9. Flag any profile where source lacks density curves entirely.
10. Flag any profile with curves from a related paper/stock family reused without explicit metadata.

## Suggested Repair Strategy After Research

Likely first implementation pass:

1. Add explicit per-field provenance metadata to profile JSON files.
2. Update README figures and captions so generated/reconstructed C/M/Y curves are not presented as manufacturer datasheet curves.
3. Add a documentation report listing source support per profile.
4. Add a profile-audit test or script that checks provenance metadata is present for each major field.
5. Only then consider constrained refits for high-risk profiles.

For Kodak Portra 400 specifically, a constrained refit can be useful, but should be labeled as reconstructed. It should preserve official `Minimum Density` and `Midscale Neutral` curves while fitting plausible C/M/Y basis curves under smoothness, nonnegative dye absorption, realistic peak locations, and neutral-print constraints.
