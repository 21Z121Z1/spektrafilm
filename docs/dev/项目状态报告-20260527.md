## 1. 项目概述

### 1.1 功能定位

Spektrafilm 是一个**模拟胶片摄影光谱特性**的图像处理应用。它通过光谱模拟管线，将数字图像转换为具有真实胶片质感的照片，涵盖：

- **胶片曝光模拟**：光谱上采样、密度曲线、耦合剂反应
- **冲印模拟**：密度光谱计算、扩散滤波、颗粒噪声
- **扫描模拟**：CMY 到 XYZ 色彩转换、黑白校正、眩光模型
- **HDR 照片输出**：增益图（Gain Map）HDR 导出、SDR 基底保持
- **色彩管理**：ACEScg 工作空间、ICC 配置文件嵌入、CCTF 编解码

### 1.2 技术栈

| 层级 | 技术 | 版本 |
|------|------|------|
| **语言** | Python | 3.13+ |
| **GUI 框架** | Qt (PySide6) + napari | 0.6.6 |
| **数值计算** | NumPy | 2.4+ |
| **色彩科学** | colour-science | 0.4.6+ |
| **图像 I/O** | OpenImageIO | 3.1.11+ |
| **GPU 加速** | MLX (Apple Metal) / CuPy (CUDA) | 可选 |
| **JIT 加速** | Numba | 0.64+ |
| **信号处理** | SciPy / pyFFTW | 1.17+ / 0.15+ |
| **曲线拟合** | lmfit | 1.3.2+ |
| **RAW 处理** | rawpy (LibRaw) | 0.26+ |
| **元数据** | exiv2 (pyexiv2) | 0.18+ |
| **许可证** | GPLv3 | — |

### 1.3 架构模式

项目采用**分层管线架构**：

```
输入 RGB 图像
    ↓
[预处理] 自动曝光 → 裁剪缩放
    ↓
[曝光阶段] 光谱上采样 → 高光增强 → 扩散滤波 → 高斯模糊 → 光晕 → log10
    ↓
[显影阶段] 密度插值 → 耦合剂 → 颗粒模拟
    ↓
[冲印曝光] 密度光谱计算 → 光强转换 → 扩散滤波 → log10
    ↓
[冲印显影] 密度插值
    ↓
[扫描阶段] CMY→XYZ → 黑白校正 → 眩光 → XYZ→RGB → 高斯模糊+USM → CCTF编码
    ↓
输出 RGB 图像
```

核心抽象层为 `ArrayBackend` 协议，支持 NumPy/CuPy/MLX 三种后端，实现 CPU/GPU 透明切换。

### 2.2 核心管线详解

管线核心在 `runtime/pipeline.py`（641 行）：

1. **预处理** (`_preprocess_input_image`): 类型转换、通道裁剪、自动曝光
2. **GPU 分块** (`_process_preprocessed_with_gpu_tiles`): 默认 2M 像素/块，可配置
3. **曝光阶段** (`filming.py`): 光谱上采样 → 高光增强 → 扩散滤波 → 高斯模糊 → 光晕 → log10
4. **显影阶段** (`filming.py`): 密度插值 → 耦合剂反应 → 颗粒模拟
5. **冲印曝光** (`printing.py`): 密度光谱 → 光强 → 扩散 → log10
6. **冲印显影** (`printing.py`): 密度插值
7. **扫描阶段** (`scanning.py`): CMY→XYZ → 黑白校正 → 眩光 → XYZ→RGB → USM → CCTF

**关键数据维度：** 光谱范围 380-780nm，步长 5nm，共 81 个波长。

## 7. GPU 加速现状与精度保证

### 7.1 后端架构

```
ArrayBackend 协议（gpu/backend.py）
    ├── NumpyBackend    — CPU 回退，始终可用
    ├── MlxBackend      — Apple Metal（macOS Apple Silicon）
    └── CupyBackend     — CUDA（NVIDIA GPU）
```

**选择级联：** `auto` → MLX/Metal → CuPy/CUDA → NumPy 回退。

### 7.2 GPU 内核覆盖

| 内核类别 | 文件 | 操作 | 后端支持 |
|----------|------|------|----------|
| 色彩变换 | `gpu/kernels/color.py` (315行) | 3×3 矩阵乘法、CCTF 编解码、高光增强 | NumPy + MLX Metal + CuPy |
| 密度计算 | `gpu/kernels/density.py` (486行) | 1D 插值、einsum、10^x | NumPy + MLX Metal + CuPy |
| 空间滤波 | `gpu/kernels/filters.py` (637行) | 高斯 FIR/IIR、FFT 卷积、反射填充 | NumPy + MLX Metal + CuPy |
| LUT 采样 | `gpu/kernels/lut.py` (533行) | 2D Mitchell-Netravali 立方、3D 三线性 | NumPy + MLX Metal + CuPy |

### 7.3 精度保证机制

**核心约束（CLAUDE.md）：** GPU 输出必须与 CPU/NumPy 输出在 float32 精度内数值一致（`atol=1e-6`）。

**实施措施：**
- 全程 float32（无 float16，除非用户显式选择）
- 相同算法、相同运算顺序
- 每个 GPU 内核都有对应测试断言 `np.allclose(gpu_result, cpu_result, atol=1e-6)`
- 如果 GPU 后端无法匹配精度，回退到 CPU

**测试覆盖：** 7 个 GPU 专用测试文件 + 1 个精度验证文件，覆盖色彩链、密度、滤波、高光增强、LUT、管线全流程。

### 7.4 GPU 分块处理

`pipeline.py` 实现了自动 GPU 分块：
- **默认预算：** 2,000,000 像素/块（~24MB float32 RGB）
- **配置方式：** `SPEKTRAFILM_GPU_TILE_PIXELS` 环境变量
- **重叠计算：** 基于镜头模糊、光晕散射、扩散尺寸自动计算

### 7.5 已知限制

- **CuPy 后端无内存池管理：** GPU 内存在管线运行间不会释放
- **MLX 后端无内存限制设置：** 可能在 Apple Silicon 上导致 OOM
- **无 tracemalloc 集成：** 内存问题难以诊断

## 8. Halide/Android 移植可行性评估

### 8.1 Halide 概述

Halide v21.0.0 是一个图像处理 DSL，核心优势：**算法与调度分离**。单管线定义可编译到 CPU (x86/ARM)、CUDA、Metal、Vulkan、OpenCL。

### 8.2 可移植性评估

| 操作类别 | 数量 | 可移植性 | Halide 适配 |
|----------|------|----------|-------------|
| 逐元素数学（exp, log, pow, select） | ~15 | **优秀** | 原生 Halide |
| 矩阵乘法（3×3, einsum） | ~8 | **优秀** | Halide 约简 |
| 1D 插值 | ~4 | **优秀** | Halide + clamp |
| 2D/3D LUT 采样 | ~3 | **优秀** | Halide + lookup |
| 高斯模糊（FIR） | ~5 | **优秀** | Halide convolve |
| 高斯模糊（IIR） | ~3 | **良好** | Halide scan |
| 指数滤波 | ~3 | **良好** | 多重高斯 pass |
| FFT 卷积 | ~2 | **中等** | 外部 FFT 或空间域分解 |
| 随机操作（RNG） | ~3 | **差** | 预处理 C++ RNG |
| 色彩科学初始化 | ~10 | **不适用** | 预计算静态数据 |
| 文件 I/O | ~5 | **不适用** | 原生 Android API |
| GUI | 24 文件 | **不适用** | Kotlin/Jetpack Compose |

**结论：** ~85% 的计算密集操作可直接用 Halide 表达。剩余 15%（FFT、RNG）可通过混合方案处理。

### 8.3 依赖替换策略

| 依赖 | 替换方案 | 工作量 |
|------|----------|--------|
| colour-science | 预计算矩阵 + 静态光谱数据 | 中 |
| scipy | 大部分已被自定义实现替代 | 低-中 |
| NumPy | Halide 替换计算图 | **这就是移植本身** |
| Numba | Halide 替换（已有 Metal/CuPy 参考） | 低 |
| opt-einsum | 嵌套循环或 BLAS | 低 |
| matplotlib/napari/qtpy | 跳过（GUI 用 Kotlin 重写） | 不适用 |

### 8.4 移植路线图

| 阶段 | 时间 | 目标 |
|------|------|------|
| **阶段 1：提取 C++ 计算核心** | 2-3 月 | 纯 C++ 库，无 Python 依赖，输出与 Python 版本一致 |
| **阶段 2：Halide 重写** | 2-3 月 | 用 Halide 管线替换性能关键 C++ 循环，ARM 优化 |
| **阶段 3：Android 集成** | 1-2 月 | JNI 桥接、Kotlin UI、图像 I/O、配置文件管理 |

### 8.5 关键风险

| 风险 | 等级 | 缓解方案 |
|------|------|----------|
| 颗粒模型随机性 | 高 | 预处理 C++ RNG → Halide buffer |
| colour-science 依赖深度 | 高 | 热路径已预计算，影响低 |
| FFT 扩散滤波 | 中 | 小核用空间域卷积，或集成 FFTW |
| 数值精度一致性 | 中 | ARM NEON float32 满足 `atol=1e-6` |
| 配置文件数据大小 | 低 | 按需加载，活跃管线 ~50KB |
