# 原生 Metal 空间滤波实验

状态：实验。基线为 `develop @ 5d14af4`。这是独立的高斯滤波执行器，
不是完整胶片管线，也不替换现有 MLX 后端。
[英文原文](native-metal-spatial.md)

## 事实来源与范围

Python 继续定义模型。`prepare_gaussian` 从现有
`utils/fast_gaussian_filter.py` 读取分派阈值、FIR 权重和 YvV 系数，
生成不可变执行数据。C++/Metal 不重复计算系数，也不读取胶片 profile。
现有生产调用点、默认后端、随机数、profile 和 FFT 路径均不改变。

架构动机来自对 SpektraLab 的审阅；新增代码依据本仓库的 CPU 实现独立编写，
未导入对方的源码、资源或第三方依赖。此前已经接触过对方源码，因此不声称
具备人员隔离的严格净室开发条件。代码继续采用本仓库的 GPL-3.0-or-later 许可。

## 契约

输入须为有限、连续、本机字节序的 float32 数组，形状为 `HxW` 或 `HxWxC`。
通道数为 1–4，单边为 1–16384 像素，sigma 不超过 256 像素，FIR 半径不超过 64。
非正 sigma 为恒等操作。不支持的输入会失败，不会静默转换、裁剪、编译或回退。

FIR 按纵向、横向执行，边界为半采样对称反射，并覆盖单像素轴。
IIR 按横向、纵向执行；每轴依次前扫和后扫，递归初始状态复制端点样本。
权重、系数与递归状态使用双 float32 表示，中间图像仍为 float32。
这是 CPU 模型的离散递归，不代表与解析高斯或 MLX FFT 响应相同。

测试同时对照 CPU float32 存储和 CPU float64，固定容差为
`atol=1e-6, rtol=1e-6`。重复原生运行及恒等通道另做逐位检查。
这不等于全管线逐位一致或物理胶片验证，也不允许降低现有生产门槛。
Metal 次正规数行为不被声明为与 CPU 逐位相同。

## 执行与所有权

C ABI 位于 `spatial.h`，Apple 适配层位于 `spatial.mm`。
`spatial_math.h` 与仅供测试的主机驱动共享算术；测试驱动不进入产品动态库。
执行层不依赖 MLX 或第三方原生运行时。

每个上下文串行执行，仅保留输入、暂存、输出三个缓冲区及常量。
同一命令缓冲区中的独立编码器负责依赖顺序，CPU 只在提交结束后等待一次。
命令成功完成且结果有限后，才复制到独立的 NumPy 输出数组。

分配前检查 `3 * input.nbytes + constant_bytes` 上限。它不包含驱动及
Python/NumPy 内存，不能当作 RSS 或 physical footprint 上限。
尺寸变化时先释放旧缓冲区；`release_memory()` 清理保留缓冲区；
`close()` 可重复调用。Python 包装层串行化关闭和执行；C 调用者不得并发销毁。

本阶段有一次图像上传与回读，没有零拷贝纹理输出、异步渲染、负片缓存或完整图。
横向 IIR 尚未做转置优化。不声明性能提升。

## 构建与验证

在 macOS 15+、具备 Xcode Metal 工具链的环境中，从仓库根目录执行英文文档的命令。
构建显式启用 safe/precise 数学并关闭隐式融合；运行时算术探针检查编译语义。
macOS 测试还会构建故意使用 fast math 的库，验证它被拒绝。
源码与产物哈希拒绝过期或替换到一半的构建；导入和渲染不会自动编译。

现有 SDR workflow 新增按变更触发的 Linux/macOS 原生验证。
Linux 仅验证主机算术与契约；macOS 必须编译并运行 Metal，缺少编译器或设备即失败。
依赖冻结，JUnit 证据上传，既有 conformance 验证保留。
基准程序仅测同步高斯滤波，不代表 RAW 到胶片的端到端耗时；
缓冲区字节数也不代表进程峰值内存。

## 接入门槛与后续顺序

接入生产前，同时比较完整空间滤波链与目标 CPU 参考及现有 MLX FFT 路径，
如实报告差异，不能把模型变化称作性能优化。同机同配置验证边界、脉冲、
大 sigma、混合通道、HDR 值及 12/50 MP，再运行现有精度阶梯和完整非 GUI 测试。
通过前保持现有默认后端。

颗粒属于下一项独立且版本化的采样契约：Philox 不能承诺保留现有 MLX 的逐像素
随机实现，必须验证分布、空间及通道相关性和功率谱，且不降低现有门槛。
负片缓存和纹理互操作在生命周期验证后推进；不为删除 Python 而复制 profile 或色彩模型。
